1. 为什么选择 Hexo？

市面上有很多博客方案，从零代码平台到纯手写网页都有。Hexo 的优势在于：

  • 完全免费：不需要服务器、不需要数据库
  • 无需后端运维：没有数据库、没有后台管理、没有安全风险
  • 速度快：生成纯静态 HTML 页面，加载速度极快
  • 专注写作：用 Markdown 格式写文章，无需关注排版
  • 主题丰富：几百款精美主题，一键切换
  • 部署简单：推送到 GitHub 即可自动发布

2. 博客技术方案对比

方案 适合人群 优点 缺点 费用
Hexo / Hugo / Jekyll 技术爱好者、开发者 免费、快速、可控 需要学习基础命令 免费
WordPress 追求功能丰富的用户 插件多、功能强大 需要服务器、维护成本高 需服务器费用
Notion + NotionNext 不想碰代码的人 所见即所得 依赖第三方、可定制性弱 免费/付费
知乎 / 公众号 / 简书 只想写内容的人 零门槛、有流量 平台限制、不能自定义 免费
手写 HTML 前端开发者 完全可控 维护成本高、不适合文章多 免费

总结：

  • 如果你不想花一分钱，想要自己的域名，愿意学一点点基础操作 → 选 Hexo
  • 如果你完全不想碰任何技术 → 选 知乎 / 公众号 或 Notion
  • 如果你需要复杂功能（评论系统、会员系统等） → 选 WordPress

10. 后续维护：更新博客

以后写新文章或修改旧文章的流程：

10.1 每次部署会全部重新生成吗？

是的，每次运行 hexo generate 都会：

  1. 清空 public/ 文件夹
  2. 重新生成所有页面（首页、文章页、分类页、标签页、归档页）
  3. 推送到 GitHub

这意味着：

  • ✅ 你不用担心遗漏，每次部署都是完整的
  • ⚠️ 文章多了生成会稍慢，但通常也就几秒到几十秒

Q2: 部署失败，提示无法连接 GitHub

原因：GitHub 仓库地址配置错误，或网络问题。

解决：

  1. 检查 _config.yml 中的 repo 地址是否正确
  2. 确认 GitHub 仓库已创建
  3. 确认已推送源代码到 GitHub

Q3: 部署成功但访问 404

原因：GitHub Pages 需要时间生效，首次部署可能延迟 1-2 分钟。

解决：等待几分钟再刷新，或检查 GitHub 仓库的 Settings → Pages 设置。
